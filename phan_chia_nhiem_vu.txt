============================================================
NHIỆM VỤ 1 - BACKEND CORE & QUẢN LÝ BÀN/PHÒNG
============================================================
Trọng tâm: Nền tảng hệ thống, phân quyền, quản lý không gian nhà hàng

PHẦN 1: THỰC THỂ CẦN XÂY DỰNG
------------------------------
1. Khu vực & Phòng
   • Class Area (Khu vực)
   • Class Room (Phòng) với 5 loại: VIP, thường, hội nghị, gia đình, sân vườn
   • Thuộc tính: mã, tên, loại, sức chứa, phụ thu (VIP 20-30%, thường 0%), tiện nghi
   • Methods: get_surcharge(), get_room_type()

2. Bàn ăn
   • Class Table
   • Thuộc tính: mã bàn, khu vực/phòng, tên, số chỗ, vị trí (x,y), trạng thái
   • Trạng thái: Trống, Đã đặt, Đang phục vụ, Đã đặt cọc, Bảo trì
   • Methods: change_status(), is_available()

3. Người dùng & Phân quyền
   • Class User với hash mật khẩu SHA-256 + salt
   • Enum Role: ADMIN, STAFF
   • Methods: hash_password(), verify_password(), check_permission()
   • Quản lý 4 tài khoản mặc định: admin, manager, staff01, staff02


PHẦN 2: CHỨC NĂNG CÀI ĐẶT
------------------------------
Chức năng 1: Quản lý bàn, khu vực và phòng
   • CRUD khu vực, phòng, bàn
   • Tìm kiếm theo từ khóa, khu vực, loại phòng, số chỗ, trạng thái
   • Đổi trạng thái bàn/phòng nhanh chóng
   • Quản lý phụ thu theo loại phòng

Chức năng 5: Tài khoản và phân quyền
   • Đăng nhập, đăng xuất, đổi mật khẩu
   • Phân quyền 2 cấp (Admin toàn quyền, Staff giới hạn)
   • Quản lý người dùng (chỉ Admin)

Chức năng 7: Custom Widget TableWidget
   • Kế thừa tk.Canvas vẽ sơ đồ bàn/phòng
   • Màu sắc theo trạng thái (VIP: vàng, thường: xanh)
   • Kéo thả sắp xếp vị trí bàn
   • Click xem thông tin chi tiết


PHẦN 3: DELIVERABLES (KẾT QUẢ BÀN GIAO)
------------------------------
✓ Module quan_ly_ban_phong.py (Area, Room, Table classes)
✓ Module nguoi_dung.py (User, authentication, permission)
✓ Module table_widget.py (Custom Canvas widget)
✓ Database schema: bảng areas, rooms, tables, users
✓ Unit test cho phân quyền và đổi trạng thái bàn


============================================================
NHIỆM VỤ 2 - KHÁCH HÀNG & ĐẶT BÀN/PHÒNG
============================================================
Trọng tâm: Quản lý khách hàng đa nhóm, quy trình đặt chỗ, xử lý giao dịch

PHẦN 1: THỰC THỂ CẦN XÂY DỰNG
------------------------------
1. Khách hàng
   • Class Customer
   • Thuộc tính: mã, họ tên, SĐT, email, loại_khach, hạng_VIP, tổng_chi_tiêu
   • Enum CustomerType: VIP, VANGLAI, DOITAC
   • Enum VIPTier: Standard, Silver, Gold, Diamond
   • Methods: update_vip_tier(), get_discount(), get_customer_type()
   • Validate Regex: SĐT VN, email, họ tên

2. Phiếu đặt bàn
   • Class Reservation
   • Thuộc tính: mã đặt, khách, bàn/phòng, ngày, giờ, số khách, thời lượng, trạng thái, tiền_cọc, món_đặt_trước, ghi_chú
   • Enum Status: Chờ_xác_nhận, Đã_xác_nhận, Đã_cọc, Đã_hủy, Hoàn_thành
   • Methods: check_time_overlap(), calculate_deposit(), confirm(), cancel()
   • Logic kiểm tra trùng thời gian (cùng bàn/phòng, cùng ngày, overlap)


PHẦN 2: CHỨC NĂNG CÀI ĐẶT
------------------------------
Chức năng 2: Quản lý đặt bàn và đặt phòng
   • Tạo phiếu đặt bàn/phòng mới
   • Kiểm tra trùng thời gian tự động
   • Kiểm tra đủ chỗ ngồi
   • Xác nhận, hủy, hoàn thành đặt bàn/phòng
   • Chuyển bàn/phòng cho đặt bàn hiện tại
   • Quy trình đặt phòng VIP riêng:
     - Cọc trước 50%
     - Xác nhận qua điện thoại
     - Ưu tiên khách VIP và đối tác

Chức năng 3: Quản lý khách hàng
   • CRUD khách hàng với validate Regex
   • Phân loại 3 nhóm: VIP, vãng lai, đối tác
   • Tự động nâng hạng VIP theo tổng chi tiêu:
     - Standard: < 5 triệu
     - Silver: 5-20 triệu
     - Gold: 20-50 triệu
     - Diamond: >= 50 triệu
   • Tìm kiếm theo tên, SĐT, email, loại khách, hạng VIP
   • Chính sách ưu đãi:
     - VIP: giảm 10-15%, ưu tiên phòng VIP
     - Đối tác: thanh toán công ty, xuất hóa đơn VAT
     - Vãng lai: giá niêm yết

------------------------------

✓ Module dat_ban.py (Reservation class + overlap check)

✓ Unit test cho kiểm tra trùng thời gian và phân hạng VIP
✓ Test case: 3 loại khách hàng với quy trình đặt khác nhau

NHIỆM VỤ 3 - THỰC ĐƠN & THỐNG KÊ BÁO CÁO
============================================================
Trọng tâm: Quản lý món ăn đa hình, dashboard, báo cáo, tích hợp hệ thống

PHẦN 1: THỰC THỂ CẦN XÂY DỰNG
------------------------------
1. Món ăn - Lớp trừu tượng
   • Abstract Class MenuItem (lớp cha)
   • 4 lớp con kế thừa:
     - Appetizer (Khai vị) - thuế 5%
     - MainCourse (Món chính) - thuế 8%
     - Dessert (Tráng miệng) - thuế 5%
     - Beverage (Đồ uống) - thuế 10%
   • Thuộc tính: mã món, tên, giá, danh mục
   • Abstract method: tax_rate() - đa hình trả thuế suất khác nhau
   • Method: get_final_price() = price * (1 + tax_rate())

2. Order/Hóa đơn (liên kết món ăn với đặt bàn)
   • Class OrderItem: món + số lượng + ghi chú
   • Class Order: danh sách món, tổng tiền, thuế, phụ thu phòng


PHẦN 2: CHỨC NĂNG CÀI ĐẶT
------------------------------
Chức năng 4: Quản lý thực đơn
   • CRUD món ăn với 4 loại (Appetizer, MainCourse, Dessert, Beverage)
   • Tự động tính giá sau thuế theo loại món
   • Tìm kiếm theo từ khóa, danh mục
   • Gợi ý món ăn theo loại phòng (phòng VIP: set menu cao cấp)

Chức năng 6: Thống kê và báo cáo
   • Dashboard với 4 KPI tổng quan:
     - Tỷ lệ sử dụng bàn/phòng
     - Tổng số đặt bàn
     - Số lượng khách hàng
     - Doanh thu
   • Biểu đồ đường: đặt bàn 14 ngày gần nhất
   • Biểu đồ tròn: trạng thái bàn hiện tại
   • Biểu đồ phân loại khách hàng: tỷ lệ VIP/vãng lai/đối tác
   • Top 5 khách hàng thân thiết
   • Doanh thu theo loại phòng (VIP vs thường)
   • Xuất báo cáo CSV (đặt bàn, khách hàng)
   • Xuất báo cáo TXT (tổng hợp)

PHẦN 3: TÍCH HỢP & DỮ LIỆU MẪU
------------------------------

   • Tạo dữ liệu mẫu:

     - 30 món ăn (đủ 4 loại)
     - 10 phiếu đặt bàn mẫu
   • Viết tài liệu hướng dẫn sử dụng
   • Test tích hợp toàn hệ thống

MA TRẬN PHỤ THUỘC (DEPENDENCY MATRIX)
============================================================

Module của A (bàn/phòng/user) → B cần dùng để tạo phiếu đặt
Module của B (khách/đặt bàn) → C cần dùng để thống kê
Module của C (thực đơn) → B cần dùng khi tạo order trong đặt bàn

→ Cần họp sync 2 lần/tuần để thống nhất interface giữa các module
